# 컬러·팔레트·그라디언트 적용 노트

아래 판단과 예시는 이 사용자용으로 새로 작성했다. 큐시트의 원문이나 원저자의 제작 방법을 인용한 것이 아니다.

## 브랜드·이미지 기반 팔레트

색상 키워드 탐색, 작품의 색 배치, 브랜드 코드 모음은 출발점이다. 다른 브랜드의 기준색을 새 브랜드의 공식 색이라고 쓰지 않는다. 콘텐츠 면적과 배경에 적용한 후 선택한다.

## 명암 단계·투명색

밝기 단계가 눈에 균등하게 보이는지와 실제 대비를 따로 확인한다. OKLCH 등 색 공간은 도구이며 자동 정답이 아니다. 투명색은 최종 합성 배경과 함께 비교한다.

## 그라디언트·움직이는 표면

정적 CSS, 원뿔/메시, 셰이더 방식의 차이를 보고 매체에 맞게 선택한다. 글자 뒤의 변화·밴딩·이미지 내보내기·모션 감소 대체를 확인한다. 장식 배경이 정보 읽기를 방해하면 낮춘다.

## 관찰을 결과물로 옮기기

참고한 화면의 URL과 관찰한 특징을 실제 변경에 연결한다. 예를 들어 “메뉴가 예쁨” 대신 “주요 이동과 보조 행동의 시각적 무게가 구분됨 → 현재 메뉴에서 핵심 행동을 한 단계 드러냄”처럼 설명한다. 관찰하지 않은 동작이나 보이지 않는 모바일 상태를 추측으로 채우지 않는다.

“이 파란색으로 앱 색 정해줘” → 기준색만 확정하고 배경·텍스트·경고·선택 상태를 별도 역할로 설계한 후 실제 앱에서 비교한다.

## 납품

컬러 토큰(CSS/JSON 등 프로젝트 형식), 적용 예와 측정한 조합을 전달한다.

변경 파일·화면·출력과 확인 근거를 먼저 말한다. 미검증 상태를 짧게 밝히고, 요청이 끝났으면 형식적인 승인 질문을 붙이지 않는다.
