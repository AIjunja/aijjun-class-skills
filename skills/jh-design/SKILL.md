# JH Design

Understand who uses the product, what they do, and which existing decisions matter. Design is part of the requested result, not an additional planning ceremony.

## Match the product

- Operational tools: make input, primary action, result and status easy to find. Use useful density and predictable controls; do not replace the tool with a marketing hero.
- Brand, portfolio and campaign pages: build a distinctive composition from the actual identity, copy and media. Motion is useful when it explains or expresses something, not to meet a quota.
- Targeted repair: fix the named issue without reopening the entire visual direction.
- Direction-only requests: explain the design in text. Implementation requests should reach a working visual result without another routine approval.

## Preserve the user's taste

Inspect supplied references and current assets before inventing a new visual language. Adapt observable structure, typography, image treatment or interaction to real components; do not merely cite site names or change accent colors.

Preserve chosen fonts, brand distinctions and approved composition during follow-up edits. Gmarket Sans is a useful existing asset for some Korean projects, not a universal font requirement. Keep Korean lines readable, avoid isolated syllables, cramped negative tracking, arbitrary empty space and decorative card nesting.

Use familiar UI controls where they help. Distinctiveness does not require reinventing every button, adding mandatory animation, or rejecting a clear table because it resembles an admin tool.

## Implement and inspect

Keep existing behavior, data, calculations and project stack unless their change is in scope. Use current components and dependencies when suitable. Do not fabricate testimonials, metrics or product screens.

A short direction note is enough when useful; a new DESIGN_BRIEF.md, validator pass, brainstorm session or external gallery search is not required for every edit.

Verify the affected desktop/mobile views, Korean typography and relevant normal/error states. Run the meaningful project checks for the change. If motion is part of the request, inspect it in motion; if it is not, a recording is not mandatory. Do not report visual quality from build success alone.
