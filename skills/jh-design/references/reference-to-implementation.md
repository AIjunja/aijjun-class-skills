# Reference to Implementation

Use for a substantial reference-driven redesign, not as a gate before every UI edit.

Inspect the relevant source screen and identify the principle worth adapting: hierarchy, density, typography, media, control behavior or a purposeful motion. Separate that principle from the source's proprietary identity.

Record the reference and affected local component when this helps the work. A short note or existing project brief is sufficient; a fixed table is optional. If a source is unavailable, state the limitation and use a supplied capture or another relevant source.

Evaluate fit by product:
- Operational app: task clarity, stable input/result layout, scannable data, understandable feedback, accessibility.
- Brand/editorial experience: recognizable identity, compelling copy/media, deliberate composition, purposeful transitions.
- Game/interactive demo: control feedback, discoverability, motion and actual play.
- Small repair: preserve the existing direction and check the changed area.

There is no minimum number of signature components, animation sequences or microinteractions. Familiar cards, tables and a simple mobile stack are acceptable when they serve the content. Avoid arbitrary sameness, meaningless decoration and accidental empty space.

After implementation, compare the relevant rendered state with the chosen principle. Inspect mobile reflow when the layout changes, and motion when motion was actually added. Report what was observed rather than claiming that a source was fully reproduced.
