# 웹·랜딩·포트폴리오 디자인 적용 노트

아래 판단과 예시는 이 사용자용으로 새로 작성했다. 큐시트의 원문이나 원저자의 제작 방법을 인용한 것이 아니다.

## 랜딩·이커머스

고객의 문제 → 실제 제품/작품 → 판단 근거 → 다음 행동을 콘텐츠에 맞게 배열한다. 가격·후기·성과가 없으면 만들지 않는다. 제품 설명을 불필요한 카드 줄로 분해하지 않는다.

## 포트폴리오·에디토리얼

대표 작업의 탐색 순서와 프로젝트 진입을 먼저 설계한다. 큰 타이틀보다 작품의 이미지, 본인의 역할, 결과 근거가 읽히는지 본다.

## 다크 테마·반응형

밝은 화면의 색상을 반전하는 데서 끝내지 않는다. 표면 단계, 보조 글자, 테두리, 이미지, 포커스를 각각 확인하고, 정보의 중요도에 따라 모바일 순서를 정한다.

## 관찰을 결과물로 옮기기

참고한 화면의 URL과 관찰한 특징을 실제 변경에 연결한다. 예를 들어 “메뉴가 예쁨” 대신 “주요 이동과 보조 행동의 시각적 무게가 구분됨 → 현재 메뉴에서 핵심 행동을 한 단계 드러냄”처럼 설명한다. 관찰하지 않은 동작이나 보이지 않는 모바일 상태를 추측으로 채우지 않는다.

“문의 화면이 복잡해” → 메뉴 레퍼런스만 비교하고 연락 방법·응답 안내·문의 입력의 순서를 정리한다. 홈페이지 전체를 다시 꾸미지 않는다.

## 납품

실제 화면/코드, 참고한 사례에서 가져온 구조, 확인한 모바일·상호작용 상태를 함께 전달한다.

변경 파일·화면·출력과 확인 근거를 먼저 말한다. 미검증 상태를 짧게 밝히고, 요청이 끝났으면 형식적인 승인 질문을 붙이지 않는다.
