# 앱 UX·온보딩·게임 UI 적용 노트

아래 판단과 예시는 이 사용자용으로 새로 작성했다. 큐시트의 원문이나 원저자의 제작 방법을 인용한 것이 아니다.

## 온보딩

회원가입 자체보다 첫 유용한 결과에 도달하는 경로를 찾는다. 필수 정보와 나중에 입력 가능한 정보를 구분하고, 건너뛰기·재진입·권한 거절 후 행동을 설계한다.

## 검색·폼·업무 앱

검색 전/결과 있음/결과 없음/연결 실패를 구분한다. 필터의 적용 여부와 해제 방법을 드러내고, 유효성 검증과 제출 중 중복 동작을 처리한다.

## 게임 UI

로비·인벤토리·설정·보상 화면의 시각 문법을 비교한다. 키보드·패드·터치 중 실제 입력 방식에 맞춰 포커스 이동과 선택/확인 피드백을 설계한다. 게임 화면을 일반 SaaS 폼으로 바꾸지 않는다.

## 관찰을 결과물로 옮기기

참고한 화면의 URL과 관찰한 특징을 실제 변경에 연결한다. 예를 들어 “메뉴가 예쁨” 대신 “주요 이동과 보조 행동의 시각적 무게가 구분됨 → 현재 메뉴에서 핵심 행동을 한 단계 드러냄”처럼 설명한다. 관찰하지 않은 동작이나 보이지 않는 모바일 상태를 추측으로 채우지 않는다.

“검색 화면 만들어줘” → 검색창 그림만 만들지 않고 최근 검색/결과/무결과/오류와 필터 해제를 연결해 실행한다.

## 납품

행동 흐름, 실제 화면/프로토타입, 검증한 정상·복구 경로와 미구현 상태를 전달한다.

변경 파일·화면·출력과 확인 근거를 먼저 말한다. 미검증 상태를 짧게 밝히고, 요청이 끝났으면 형식적인 승인 질문을 붙이지 않는다.
