# 모션·마이크로인터랙션 적용 노트

아래 판단과 예시는 이 사용자용으로 새로 작성했다. 큐시트의 원문이나 원저자의 제작 방법을 인용한 것이 아니다.

## 상태 피드백

클릭이 접수됐는지, 처리 중인지, 결과가 나왔는지를 구분한다. 장식 스피너가 실제 진행률을 표현하는 것처럼 보이지 않게 한다.

## 스크롤·포인터·전환

스크롤 위치와 상태 변화의 인과를 유지한다. 강제 스크롤이나 커스텀 커서가 접근성과 콘텐츠 탐색을 막지 않게 하고 작은 화면에서 대체 동작을 정한다.

## 아이콘·브랜드·영상

Lottie·SVG·CSS·영상 합성은 필요한 출력에 맞춰 고른다. 브랜드 동작을 앱 전체에 강제하지 않는다. 영상은 기존 승인 프리셋과 실제 에셋의 관계를 보존한다.

## 관찰을 결과물로 옮기기

참고한 화면의 URL과 관찰한 특징을 실제 변경에 연결한다. 예를 들어 “메뉴가 예쁨” 대신 “주요 이동과 보조 행동의 시각적 무게가 구분됨 → 현재 메뉴에서 핵심 행동을 한 단계 드러냄”처럼 설명한다. 관찰하지 않은 동작이나 보이지 않는 모바일 상태를 추측으로 채우지 않는다.

“저장할 때 좀 살아있게 해줘” → 저장 요청·진행·성공/실패와 맞물린 짧은 피드백을 구현하고 실패 뒤 재시도를 실행한다.

## 납품

재생 가능한 화면/영상과 적용한 트리거·상태, 확인한 조작과 대체 상태를 전달한다.

변경 파일·화면·출력과 확인 근거를 먼저 말한다. 미검증 상태를 짧게 밝히고, 요청이 끝났으면 형식적인 승인 질문을 붙이지 않는다.
