# Offer, reading order and Korean copy

Reference basis: The Mark Marketing's landing-page guide, inspected 2026-10-28,
https://themarkmarketing.co.kr/blog/landing-page-guide . This is an original
synthesis, not a reproduction of the article or its client results.

## Decide what the visitor needs to know

1. What is offered and is it for me?
2. What will I actually do or receive?
3. Why should I trust this person/product?
4. What conditions or limitations affect me?
5. What happens when I act?

An effective hero is not a claim of guaranteed performance. Use a literal offer
as the H1 and concrete method/outcome in the support line. Put an actual service
photo, usable example or product state beside the claim it supports. Keep a hint
of the next section visible in the first viewport.

For a course, separate learner outcome from a delivery promise. A two-hour
guided deployment process is not a guarantee that every unprepared account will
be deployed. Explain prerequisites and adapt restricted environments without
burying the main learning value in warnings.

Use real role labels: assistant teaching, lead teaching, curriculum design and
personal prototype are different. A logo row can imply endorsement; use factual
experience descriptions instead unless the usage is authorized.

## Edit the text

The supplied AI쭌 reference pack points to Toss UX-writing principles. Apply the
principles to this task without claiming that a Toss skill was installed/read
when only the user's synthesis was available.

- Prefer the visitor's work and decision over a list of provider features.
- One sentence, one point. Keep headline, supporting copy and proof from merely
  repeating the same claim.
- Explain new vocabulary at the moment it helps an action.
- Buttons name their result: view the curriculum, open the platform, copy an
  address, draft an inquiry. Avoid generic confirm/next labels.
- Errors name the problem and the next available action. A denied clipboard
  permission should leave a visible, selectable email address.
- Keep one tone and consistent time/currency notation. Do not force English
  interface jargon into Korean copy.
- Remove empty superlatives, guilt, fake scarcity and universal guarantees.
- Do not apply a single client's preferred font, emoji or tone to all customers.

## State truth

An inquiry link opening the mail app is not an inquiry sent. A local demo that
calculates sample totals is not a live model call. A completed drawing is not a
deployed website. A source catalog HTTP200 is not a successful visual review.
Use a short explanation only where this distinction changes a reader's decision.

Free follow-up: identify what is free, when/how it happens and what is excluded.
Do not invent a number of hours or imply perpetual maintenance when the user
has approved only an additional question period.
