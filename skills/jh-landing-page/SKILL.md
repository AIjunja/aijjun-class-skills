# JH Landing Page

Make the offer understandable, credible and actionable. A polished information
document is not automatically a useful landing page. Preserve the actual offer,
existing brand decisions and user-controlled external actions.

## Start from the offer

Read the current page and supplied assets before writing a replacement. Establish
the audience, literal offer, outcome, proof, main action and conditions from the
available context. Do not invent urgency, customer logos, satisfaction, revenue
or guaranteed completion. Ask only when a missing fact changes those claims.

Keep one main conversion, such as an inquiry, booking or purchase. Supporting
curriculum, demo and portfolio links can reduce uncertainty without competing
with the main action. Do not install a form backend when a working email or
booking destination is sufficient.

For a one-off bounded repair, repair that issue. For a new page or redesign, use
this short chain: offer and evidence -> section order -> visual reference
mapping -> working implementation -> viewport and behavior review.

## Select references by the decision they help

Read [references/catalog.md](references/catalog.md) to find sources for structure,
navigation, typography, evidence, interaction or motion. The catalog records a
dated review, not perpetual availability or a reuse license. Recheck selected
examples when their current appearance matters. When asked to inspect a whole
collection, state the exact seed/direct-link scope, deduplicate it, and distinguish
HTTP access, content reading, visual review and interaction testing.

Choose a coherent page structure and a small set of interactions that serve this
offer. More references do not mean mixing more styles. Record concrete mappings:
which section pattern, text hierarchy or movement is adapted, and why it helps
this audience. Do not cite gallery names without inspecting an actual example.

## Build the reading path

- First viewport: the offer/category is the main heading, with its audience,
  benefit and next action easy to locate. Use real product/service media or an
  informative immersive interaction, not a decorative fake dashboard.
- Follow the reader's questions: relevance, mechanism, outcome, credibility,
  conditions and action. Reorder sections when the audience requires it rather
  than using a fixed three-card template.
- Show actual work, a small usable sample or verifiable evidence. Label samples,
  reconstructions and synthetic data. Never present a staged animation as a
  successful live AI integration.
- Keep contact actions real. A mailto link opens a draft, copying copies, and a
  successful form state requires actual acceptance. Do not simulate a sent inquiry.
- Keep legal, pricing, account, support and free-offer conditions near the decision
  they affect. Do not turn a free question period into unlimited development.

For copy work, read [references/conversion-copy.md](references/conversion-copy.md).

## Make the design specific

Use the user's current brand and inspected composition. `jh-design` is the shared
visual companion when available, not a required installation. Preserve chosen
fonts unless replacing them is part of this redesign. Confirm webfont and asset
use permissions; a gallery listing is not a template license.

Keep Korean words and meaningful phrases together. Fix orphaned final syllables,
cramped controls and awkward numerical labels, not only page-wide overflow.
Hero-scale type belongs in the hero; dense tables and practical details need a
smaller hierarchy. Keep sections unframed and reserve cards for actual repeated
items or framed tools. Do not turn the page into nested cards.

## Motion must explain or express

Read [references/motion-recipes.md](references/motion-recipes.md) when adding or
revising motion. Reuse the current stack. CSS/WAAPI/IntersectionObserver can be
enough; Motion or GSAP is useful for genuinely linked timelines. Do not rewrite a
static page into React merely to add a fade.

Prefer a signature interaction plus restrained support. Animate the actual object
or state: input becomes output, a curriculum changes day, a real preview reveals
detail. Use transform and opacity before expensive blur/layout effects. Keep text
selectable, default scrolling normal, coarse-pointer behavior usable and reduced
motion complete. Do not replace the system cursor or trap scrolling by default.

## Inspect before delivery

Read [references/acceptance.md](references/acceptance.md). Inspect the full reading
path and normal/error states at desktop and narrow mobile widths. Check motion in
motion with before/during/after states. Build success and a screenshot do not prove
interaction quality, actual submission or deployment.

Publish only to the requested/approved audience and environment; preserve the
existing Site identity and separate other live sites. Do not infer email-send,
payment or account permission from approval to build. Report the real URL and
what was verified, with remaining limits.
