# 목업·사진·영상·디자인 리소스 적용 노트

아래 판단과 예시는 이 사용자용으로 새로 작성했다. 큐시트의 원문이나 원저자의 제작 방법을 인용한 것이 아니다.

## 목업·스크린샷

기기 목업은 화면 내용을 설명하는 보조다. 그림자가 UI를 가리거나 실제 앱의 비율을 왜곡하지 않게 한다. 실제 캡처와 합성 장면을 구분한다.

## 사진·영상·음악

구도·표정·빛·색조·해상도·오디오 길이를 전달 매체와 맞춘다. 스톡이 실제 고객이나 사용자 경험의 증거처럼 보이지 않게 한다. 라이브러리 전체 조건보다 개별 파일 조건을 확인한다.

## 키트·플러그인·더미

Figma/Sketch/XD/Photoshop/코드 태그는 발견 경로다. 실제 지원 버전과 도구를 확인한다. 한글 더미는 시안에만 쓰고 최종 원고와 혼동하지 않게 교체한다.

## 관찰을 결과물로 옮기기

참고한 화면의 URL과 관찰한 특징을 실제 변경에 연결한다. 예를 들어 “메뉴가 예쁨” 대신 “주요 이동과 보조 행동의 시각적 무게가 구분됨 → 현재 메뉴에서 핵심 행동을 한 단계 드러냄”처럼 설명한다. 관찰하지 않은 동작이나 보이지 않는 모바일 상태를 추측으로 채우지 않는다.

“만든 앱 홍보 이미지 만들어줘” → 현재 앱을 캡처하고 실제 화면을 기기 목업에 넣은 뒤 결과가 잘리지 않는지 확인한다.

## 납품

편집 원본, 실제 내보낸 이미지/영상, 사용 에셋과 개별 출처를 전달한다.

변경 파일·화면·출력과 확인 근거를 먼저 말한다. 미검증 상태를 짧게 밝히고, 요청이 끝났으면 형식적인 승인 질문을 붙이지 않는다.
